## 3. 架构原则（规划）

- 组件化：表现层逻辑挂在 Cocos 组件（Component）上，使用引擎生命周期与调度。
- 逻辑与表现分离：数值计算（伤害、经验曲线、掉落）尽量写成纯函数/纯类，便于 tests 验证。
- 模块通信：跨模块通过 core 的事件总线或明确接口，不直接改写其他模块内部状态。
- 数据驱动：怪物、技能、宠物、波次数值放入 resources/configs 的 JSON，代码读取配置。
- 存档：本地存储（微信环境经 Cocos sys.localStorage 适配），字段与版本策略待定。
- 依赖方向：ui → progression/combat → data；core 提供基础设施；避免循环依赖。
