## 1. 测试分层策略（规划）

### 1.1 纯逻辑单元测试（tests/）

对象：与引擎解耦的数值与规则逻辑。测试运行方式待定（候选：Node 环境下的轻量 TS 测试，不引入重型框架，需用户确认后再引入依赖）。

| 模块 | 测试点 | 验收条件 |
|---|---|---|
| progression/LevelSystem | 经验累积、升级阈值曲线 | 给定经验序列，升级次数与时机与配置一致 |
| progression/UpgradeOptionPool | 三选一生成 | 每次恰好 3 个不重复候选；权重规则符合配置 |
| combat/DamageCalculator | 伤害公式 | 边界值（0 伤害、防御溢出）结果正确 |
| monsters/WaveSchedule | 波次解析 | 10 分钟时间轴上的生成事件与配置一致 |
| data/SaveSystem | 存档序列化/反序列化 | 写入后读取字段一致；损坏数据有兜底 |
| progression/RunResult | 金币结算公式 | 击杀数/存活时长映射金币正确 |

### 1.2 编辑器内功能验证（人工 + 截图/日志）

| 功能 | 验收条件 |
|---|---|
| 虚拟摇杆 | 单指拖动输出方向向量，角色随之移动，松手停止 |
| 自动攻击 | 无需操作即可命中范围内怪物 |
| 怪物生成与追踪 | 按波次生成，持续朝玩家移动，无卡死 |
| 经验与升级 | 击杀掉落经验，拾取升级，弹出三选一且暂停局内时间 |
| 三选一应用 | 选择后对应技能/属性立即生效 |
| 宠物 | 跟随玩家并按设计辅助攻击 |
| BOSS 与胜负 | BOSS 按时出场；击杀判胜、玩家死亡判负 |
| 结算与金币 | 结算数据正确，金币入账并持久化 |
| 本地存档 | 重启游戏后存档数据保留 |

### 1.3 微信小游戏平台验证

| 项目 | 验收条件 |
|---|---|
| wechatgame 构建 | 构建成功，微信开发者工具可运行（AppID 待配置） |
| 真机预览 | 至少 1 台真机可完整跑完一局 |
| 性能 | 大量怪物场景下帧率可接受（目标值待定，建议 ≥ 30fps） |
| 首包体积 | 符合微信平台限制（主包 ≤ 4MB，以平台当期规则为准） |
| 本地存储 | sys.localStorage 在微信环境读写正常 |
