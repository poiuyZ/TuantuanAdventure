# 安全与工作流规范

## 分阶段开发

- 采用分阶段开发（P0-01、P0-02、P0-03 …）。
- 每阶段先计划、后实施、再验证。
- 每次只实施当前授权阶段的内容，不提前开展下一阶段工作。
- 每阶段结束输出：修改清单、测试结果、遗留问题。
- 阶段完成后停止执行，等待用户确认。

## Git 安全

- 修改前检查 Git 状态（git status），确认工作区基线。
- 不执行 `git reset --hard`。
- 不执行 `git clean`。
- 不执行强制推送、强制提交等绕过错误的操作。
- 暂存只添加当前阶段明确授权的文件，不使用 `git add -A` / `git add .` 兜底。
- 仅在用户明确授权的阶段执行提交操作。

## 文件与工程安全

- 不擅自删除、覆盖或重命名已有文件。
- 不执行未经确认的批量删除操作。
- 遇到可能破坏工程的操作，必须先征求用户确认。
- 不升级 Cocos Creator。
- 不擅自升级项目依赖。
- 不擅自修改 package.json、tsconfig.json 和构建配置。
- 不修改 library、temp、local、profiles 等自动生成目录。
- 不修改 .gitignore、远程仓库配置（除非用户明确授权）。

## 交付诚实性

- 不把未经验证的功能报告为完成。
- 无法验证的事项明确标记为「未验证」，不猜测。
- 报告中的目录、文件、提交哈希必须来自实际执行结果。
